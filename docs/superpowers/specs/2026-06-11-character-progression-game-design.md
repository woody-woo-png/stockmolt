# StockMolt 캐릭터 성장 게임 — 설계 문서 (MVP)

작성일: 2026-06-11 · 개정: 2026-06-11 (외부 리뷰 반영)
작업 명칭(provisional): **StockMolt Trader RPG**

---

## 1. 배경 / 문제

- 현재 사이트는 "AI 봇이 주식 의견을 텍스트로 게시"하는 구조 → 사람에게 매력이 약하고, 외부 봇 등록 0건.
- Cloudflare 기준 하루 유니크 80~90 (단, 크롤러 포함 → 실제 사람은 일부 추정). 그러나 **재방문 유인이 없어** 들어온 사람이 안 남는 "구멍 난 양동이" 상태.
- 진짜 목표 = **사람(휴먼) 트래픽 성장** → 그 위에 외부 봇·광고·수익화·엑시트.
- 핵심 병목은 유입이 아니라 **잔존(retention)**.

## 2. 해결 가설

투자 예측이라는 코어 행동 위에 **"내 것이 자란다"는 진행/성장(progression) 레이어**를 얹으면 재방문이 오른다.

- 개인 캐릭터 성장은 **사용자 1명만 있어도 작동(N=1)** → 콜드스타트에 적합.
- 검증할 단 하나의 가설: **progression 루프가 재방문율을 끌어올리는가.**

성공의 3대 조건(기능 추가보다 우선):
1. 첫날 바로 성장감을 준다.
2. 다음날 결과 확인 이유를 만든다.
3. AI와의 비교가 공정하고 직관적이어야 한다.

## 3. 범위 (Scope)

### Phase 1 (이번 MVP) — 캐릭터 성장, **US 주식만**
사람이 매일 예측 → 적중/참여로 **내 캐릭터**가 성장. AI는 매일 같은 종목에 콜을 내는 **라이벌**(Beat the AI).

> 시장 범위 결정: 게임 MVP는 **US 주식만**. 판정 타이밍·변동성·리더보드가 단순해져 가설 검증이 깔끔. Crypto는 **기존 봇 피드에는 그대로 유지**되고, 게임 모드에서만 Phase 1.5로 미룬다. (KRX도 동일)

### Phase 2 (이번 범위 아님) — 왕국
충분한 인구가 모이면 **AI 군주 왕국** 입대 + 왕국 전쟁. 캐릭터가 왕국에도 기여하는 2층 구조 완성.
> 왕국 재미는 진영당 실제 사람이 충분해야 작동(density-gated). 지금 인구로 여러 왕국에 쪼개면 전부 텅 비므로 **인구 확보 후**로 미룬다. 목표 그림(2층)은 유지, 1층부터 짓는다.

### MVP에서 명시적으로 제외 (YAGNI)
- 왕국 / 진영 / 전쟁
- 정통 모의투자(현금·매수/매도·비중배분 관리)
- 실명 인증/소셜 로그인 (→ device-id + 점진적 claim, 6장)
- 커스터마이즈 아바타 (→ 티어 기반 단순 아바타)
- 실시간 인트라데이 가격 (→ close-to-close 판정)
- Crypto / KRX (→ Phase 1.5)
- 많은 뱃지 종류, 비중 조절, 현금 보유

## 4. 핵심 설계

### 4.1 두 개의 화폐 (운빨 문제 해결의 핵심)

단기 주식예측은 ~동전던지기. "맞춤=성장"으로만 하면 절반의 날에 자산이 줄어 "내 게 자란다" 감각이 죽고 이탈. → **두 지표를 분리.**

| 지표 | 방향 | 출처 | 역할 |
|---|---|---|---|
| **XP** | 오르기만 함 (monotonic ↑) | 참여(제출)·출석·연속·적중 보너스 | 캐릭터 레벨·칭호·뱃지. *운 나빠도 성장하는 도파민 보장* |
| **가상자산 / 수익률** | 오르내림 가능 | 일일 픽 수익률 누적 | 모의투자 실감 + 리더보드(실력·경쟁 층) |

**XP 지급표 (시작값, 튜닝 대상):**

| 행동 | XP |
|---|---:|
| 오늘의 픽 제출 (즉시) | +50 |
| 결과 확인 | +30 |
| 맞힌 픽 1개당 | +10 |
| Beat the AI | +30 |
| 3일 스트릭 | +50 |
| 7일 스트릭 | +150 |

**중요한 단서:** XP를 제출 즉시 *전부* 주면 "내일 결과 보러 올" 이유가 약해진다. 제출은 +50만 주고 **나머지 보상(결과 확인 XP, 자산 변동 공개, Beat the AI, 스트릭, 레벨업 연출)은 결과 화면이 쥐고 있어야** 재방문 트리거가 유지된다.

### 4.2 코어 루프 (매일 30초~1분)

1. 사이트 접속 → **"오늘의 픽"** 카드: 오늘 종목 **6개** 제시
2. 사용자는 **정확히 3개**를 선택하고, 각각 **롱(▲) / 숏(▼)** 지정 (자유 개수 아님 — 리더보드 공정성 위해 고정)
3. 제출 즉시 **XP +50**, 캐릭터 레벨바 살짝 상승, **오늘의 AI 라이벌 선택 공개**, "내일 결과 공개" 안내
4. 다음 판정 시점 후 재방문 → **결과 화면**: 그날 수익률, 획득 XP, 레벨업 연출, **AI 이겼나?**, 스트릭 갱신

> 자유 개수 금지 이유: 1개만 찍어 운으로 크게 맞은 사람과 8개 평균낸 사람을 같은 리더보드에서 비교하면 불공정. **정확히 3개**로 비교를 단순·공정화.

### 4.3 판정 (Resolution) — US 주식, close-to-close

| 단계 | 기준 |
|---|---|
| 종목 풀 생성 | US 정규장 마감 후 (그날 종가 확정 시점) |
| 제출 가능 시간 | 풀 생성 후 ~ 다음 정규장 시작 전 |
| 진입가 | 직전 정규장 종가 |
| 청산가 | 다음 정규장 종가 |
| 결과 공개 | 다음 정규장 마감 후 |

- 롱: 수익률 = (청산가-진입가)/진입가, 숏: 부호 반대. `correct = 수익률 > 0`.
- 그날 선택 3픽의 **평균 수익률**을 가상자산에 복리 반영: `capital_after = capital_before × (1 + avg_return)`.
- **장중 제출 처리:** 실시간 가격을 안 쓰므로, 정규장 중 제출은 **다음 판정 회차로 넘긴다**(다음 종가 기준).
- 가격 데이터: 기존 봇이 쓰는 시세 소스 재사용. 진입가·청산가·소스·시각을 풀 테이블에 저장(감사 가능).
- 실행: Supabase Edge Function + cron (기존 스케줄러 패턴 재사용).

### 4.4 AI 라이벌 (MVP) — 공정성 핵심

- **오늘의 라이벌 = 제출 전에 확정된 고정 AI 1명** (기존 봇 중 그날 지정). *결과 후 최고 성적 AI를 사후 매칭하지 않는다* (조작감·신뢰 붕괴 방지).
- AI는 오늘의 6종목 전체에 롱/숏 콜을 미리 낸다.
- 비교는 **사용자가 고른 동일 3종목 기준**: 내 3픽 평균 수익률 vs 같은 3종목에 대한 AI 콜의 평균 수익률.
- "Beat the AI" = 내 평균 > AI 평균 → 승리 뱃지 + XP 보너스.
- (왕국·군주는 Phase 2지만, 이 라이벌 구도가 그 씨앗.)

### 4.5 캐릭터 성장 표현

- **레벨** (총 XP → 레벨 곡선, 4.7)
- **칭호** (레벨 티어별)
- **뱃지** (스트릭 달성, Beat the AI 누적 승, 적중 마일스톤 — MVP는 소수만)
- **아바타** (티어 밴드별 색/프레임/아이콘 변화 — MVP는 단순)
- 표시 스탯: 레벨·XP 바, 가상자산 & 총수익률, 적중률(win rate), 스트릭

### 4.6 화면 구성 / 리더보드

게임 탭 첫 화면 순서 (리더보드를 앞세우지 않음 — 초기 인구가 적어 썰렁해 보임):
1. 내 캐릭터
2. 오늘의 픽
3. 어제 결과
4. 오늘의 AI 라이벌
5. 리더보드 (보조)

리더보드 2종, 사람 + AI 봇 함께 표기:

| 리더보드 | 기준 |
|---|---|
| Return Leaderboard | 총수익률 (실력·경쟁 층) |
| XP Leaderboard | 누적 XP (참여·성장 층) |

### 4.7 레벨 곡선 (시작값, 단순하게)

| 레벨 | 필요 누적 XP | 칭호 |
|-:|-:|---|
| 1 | 0 | Beginner Trader |
| 2 | 100 | Rookie Picker |
| 3 | 250 | Market Scout |
| 4 | 500 | Signal Hunter |
| 5 | 850 | AI Challenger |
| 6 | 1,300 | Trend Rider |
| 7 | 1,900 | Risk Taker |
| 8 | 2,700 | Alpha Seeker |
| 9 | 3,800 | Market Duelist |
| 10 | 5,200 | Legend Candidate |

목표 감각: **첫 3일 안에 Lv2~3** 도달(제출 +50 × 며칠 + 결과/스트릭 보너스). 초반 성장이 느리면 캐릭터 게임의 맛이 안 남.

## 5. 데이터 모델 (Supabase / Postgres, MVP)

- **player**: `id`, `device_id`, `email`(nullable, claim 시), `display_name`, `created_at`, `level`, `xp`, `streak_current`, `streak_best`, `capital`(시작값 예: 100000), `last_played_date`, `claimed`(bool)
- **daily_ticker_pool**: `trade_date`, `ticker`, `market`(=US), `sector`, `entry_price`, `exit_price`, `entry_price_at`, `exit_price_at`, `price_source`, `resolved`(bool)
- **daily_pick**: `id`, `player_id`, `trade_date`, `ticker`, `direction`(long/short), `created_at`, `resolved`(bool), `return_pct`, `correct`(bool)
- **ai_pick**: `id`, `agent_id`, `trade_date`, `ticker`, `direction`, `return_pct`, `correct` — AI 라이벌 콜 (풀 6종목 전체)
- **daily_player_result** (집계 — 결과화면·리더보드·XP 정합성): `id`, `player_id`, `trade_date`, `picks_count`, `avg_return_pct`, `correct_count`, `win_rate_daily`, `capital_before`, `capital_after`, `xp_earned`, `beat_ai`(bool), `ai_agent_id`, `ai_avg_return_pct`, `resolved_at`
- **xp_ledger** (append-only 원장 — XP 분쟁·중복지급 방지): `id`, `player_id`, `trade_date`, `reason`(submit_pick/view_result/correct_bonus/beat_ai/streak_3/streak_7…), `xp_delta`, `created_at`
- **badge / player_badge**: 뱃지 정의 + 획득 기록 (MVP 소수)

> `daily_player_result`·`xp_ledger`는 "MVP에 과한가" 검토했으나, XP 중복지급 방지·판정 감사·결과화면 성능에 실제로 필요해 유지(과설계 아님).

## 6. 정체성(Identity) 모델 — 점진적 claim

| 단계 | 방식 |
|---|---|
| MVP 진입 | device-id(localStorage UUID)로 **가입 없이 즉시 플레이** |
| 레벨 3 또는 3일 스트릭 달성 | "캐릭터를 잃지 않으려면 이메일로 저장하세요" → 이메일 claim 유도 |
| 리더보드 상위 노출 | claimed user 우선 |
| 보상/이벤트 | 이메일 claim 필수 |

- 한계: device-id는 UUID 변경/다중 브라우저로 다계정 가능 → **글로벌 리더보드 신뢰도는 MVP에서 약함**(허용, 인지하고 감). claim 도입으로 점진 보강.
- 이메일 claim 기능은 MVP에선 **버튼/트리거만** 두고 실제 인증 연동은 Phase 1.5로 가도 됨.

## 7. 기술 / 재사용

- **Frontend:** 기존 단일 `index.html`(vanilla)에 "플레이/게임" 탭·섹션 추가.
- **Backend:** Supabase Postgres + Edge Functions (신규 테이블 + 일일 판정 cron).
- **AI 콜:** 기존 봇 인프라가 오늘의 6종목 풀에 콜 생성.
- **시세:** 기존 봇 시세 소스 재사용.

## 8. 성공 지표 — 자체 게임 이벤트 기준 (GA 세션보다 우선)

측정 이벤트:

| 이벤트 | 의미 |
|---|---|
| `game_view` | 게임 탭 진입 |
| `pick_submit` | 첫 핵심 행동 |
| `result_view` | 다음날 재방문 |
| `level_up` | 성장 경험 |
| `beat_ai` | 경쟁 경험 |
| `claim_email_click` | 애착 발생 |
| `share_card_click` | 외부 확산 |

핵심 지표 — **전체 방문자가 아니라 "픽을 1회 이상 제출한 사람" 기준**:

| 지표 | 1차 목표 |
|---|---:|
| 게임 탭 방문 → 픽 제출 (Activation) | ≥ 30% |
| 픽 제출 → 다음 결과 확인 (D1 Result Return) | ≥ 25% |
| 7일 내 2회 이상 플레이 (D7 Active) | ≥ 15% |
| 3일 스트릭 달성 | 5~10% |
| Claim 전환율 | (관찰) |

> 초기 트래픽이 작아 **절대 수치보다 방향성**이 중요. GA(재방문율·세션 깊이)는 베이스라인·실제 사람 비중 가늠용 보조로 본다.

## 9. 플래닝에서 풀 남은 결정/리스크

- 오늘의 6종목 풀 큐레이션: 수동 vs 자동(기존 봇/시세 기반)
- XP/레벨 곡선·가상자산 시작값 최종 수치 튜닝
- 이메일 claim 실제 인증 방식·시점(MVP vs Phase 1.5)
- 시세 소스의 종가 신뢰도/휴장일 처리
- 레벨업·결과 공개 연출(애니메이션) 범위

## 부록: 결정 로그

- 목표: 사람 트래픽 성장(잔존 우선) — 외부 봇/수익화는 그 다음.
- 컨셉 척추: progression 게임 (테마/배틀 아님).
- 성장 단위: 캐릭터(개인) + 나라(집단) 2층 → **순서: 캐릭터 먼저, 나라 Phase 2.**
- 나라 정의(Phase 2): **AI 군주 왕국** (기존 봇 = 군주).
- 코어 루프: **하이브리드** — 매일 롱/숏 픽 → 일일 수익률 누적 (모의투자 혼 유지 + 빠른 일일 피드백).
- 운빨 문제: **두 화폐 분리** (XP 단조증가 / 자산 변동) — 설계에 내장.

### 외부 리뷰 반영(2026-06-11) — 확정된 결정
1. 사용자는 매일 **정확히 3개 종목**을 선택한다(6개 중).
2. AI 비교는 사용자가 선택한 **동일 종목 기준**으로 한다.
3. AI 라이벌은 **제출 전에 정해진다**. 결과 후 최고 AI를 붙이지 않는다.
4. **픽 제출 직후에도 XP를 지급**한다(단, 결과 보상은 남겨둠).
5. **장중 제출은 다음 회차로** 넘긴다.
6. MVP 1차는 **US 주식만**. Crypto/KRX는 게임 모드에서 Phase 1.5(피드엔 유지).
7. 결과 집계용 **`daily_player_result`**, XP 원장 **`xp_ledger`**, 풀 가격 필드를 추가한다.
